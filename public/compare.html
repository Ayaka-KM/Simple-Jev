1一句话结论与怎么选

只处理文字、一次问很多题、在意成本，选 Jev；要看图片、输入很长，或需要 OpenAI 的合规选项，选 Luna。

这些情况选 Luna

  • 需要看图片。Luna 能读图，每次最多 128 张；Jev 不支持图片。
  • 输入很长。超过 Jev 32,000 token 的单次输入上限时，可以用上下文 1,050,000 token 的 Luna。
  • 需要 OpenAI 的合规选项。零数据保留（ZDR）、HIPAA、数据驻留（在美国或欧洲处理请求），限直连 OpenAI 的合格客户。

这些情况选 Jev

  • 只处理文字。Jev 只接受文字和 JSON。
  • 一次要问很多题。Luna 单次最多 200 道；Jev 实测 2,048 道也能一次跑完，不过题越多错得越多。
  • 在意成本，尤其是批量。128 道是/否题时，Jev 便宜约 20 倍。
  • 希望延迟尾部更稳。p99 延迟 Jev 399 ms，Luna 980 ms。

注意两个容易踩的坑

  • Luna 有内容审核。通过 OpenRouter 调用时，只要一道题被拒答，整个请求都会失败（详见第 9 节）。
  • Jev 收到图片不会报错，但给出的答案只是乱猜（详见第 4 节）。

3决策方式

通过 OpenRouter 的统一接口 /api/alpha/decisions 调用时，两个模型的题型、请求格式、返回格式完全一样。不过两者的单次上限不同（Luna 单次最多 200 道题，Jev 单次输入上限 32,000 token），见第 5 节。

三种题型（没有其他题型）

noul 是 / 否

判断一件事成不成立，返回“是”的概率。

返回 { type, noul }

choice 单选

从几个选项里挑一个，返回选中项、每个选项的概率和置信度。

返回 { type, choice, probabilities: {选项: 概率}, confidence }

score 打分

放到一组从低到高的档位上打分。

返回 { type, score, legend, probabilities: {"0": …}, confidence }

score 是各档位编号（从 0 开始）按概率加权的平均值，所以可能落在两档之间，比如第 8 节里 Luna 打出的 1.69。

请求和返回的格式

请求（两个模型相同）：

{
  model,
  state,
  questions: {
    题名: { type, instructions, criteria }
  }
}

返回的顶层字段（两个模型相同）：answers、id、model、provider、usage。

直连 OpenAI 时的叫法（仅供了解）

OpenAI 原生接口的字段名不一样，OpenRouter 已经做了转换，通过 OpenRouter 调用时不用关心：

  • 题型叫 predicate（概率）/ choice / score；
  • 请求字段是 model、input（字符串，或含 input_text / input_image 的 user 消息）、questions 数组（每题有 name）；
  • 单选写成 choices: [{value, description}]，打分写成 levels: [{label, description}]；
  • 返回 answers 数组；单选和打分的 probabilities 是数组；
  • 某道题被拒答时，返回 type: "refusal" 的答案。

来源：OpenRouter API 参考、OpenAI Decisions 指南、实测 A

Luna 的图片怎么传

  • 放在 state 数组的最外层，写成 { "type": "image_url", "image_url": { "url": "data:image/png;base64,..." } }；数组里的文字直接写字符串。
  • 只接受 base64 data URL，类型为 image/png、image/jpeg、image/webp；不会下载远程网址。
  • 可以设置 detail（auto / low / high），它决定图片按多大尺寸计 token，见第 6 节的实测表。
  • 每次最多 128 张图。
  • 嵌在对象里的图片不会被当成图片读取。

实测：Luna 看图

  • 测试图：左半红、右半蓝、蓝色区域里有个白色方块。Luna 答对左半是红（95%）、有白色方块（概率 1）、方块在右半（69%）。detail=low 结果相同。
  • JSON 对象和图片可以一起放在 state 数组里，正常回答（noul 0.93）。
  • 嵌在对象里的图片确实读不到：答案变成乱猜（左半颜色答“蓝”60%，实际是红）。
  • 传远程网址 → HTTP 400OpenAI Decisions accepts only embedded base64 data URL images
  • 传 129 张图 → HTTP 400OpenAI Decisions accepts at most 128 images, got 129

Jev 收到图片不报错，会悄悄乱猜

把图片发给 Jev，照样返回 HTTP 200 和一组概率，但答案只是乱猜。同一张测试图（左半红、右半蓝）：

  • 问左半是什么颜色：红 33% / 绿 30% / 蓝 24% / 黄 13%；
  • 问白色方块在哪：58% 答“没有白色方块”。

要看图请用 Luna。Simple Jev 里选 Jev 这类纯文字模型时，图片上传会被禁用。

输出

两者都只输出“决策”（概率、选项或分数），不生成文字。输出 token 都免费：Luna 的 usage.output_tokens 一直是 0；Jev 会报告输出 token 数，但不收费。

Luna 每张图片多算多少 token（实测）

在同一个请求里加一张 JPEG 图，输入 token 会多出下表的数量（和题目内容无关），按 detail 设置分列。Jev 不支持图片，所以只有 Luna：

图片尺寸 detail=auto（默认） detail=high detail=low
512×384 +193 +193 +193
768×1024（竖图） +769 +769 +193
1024×256（长条） +257 +257 +65
1024×576（16:9） +577 +577 +145
1024×768（4:3） +769约 $0.000077 +769 +193
1024×1024（正方形） +1,025约 $0.0001 +1,025 +257
2048×1536 +3,073约 $0.00031 +2,452 +193
  • 规律：图片被切成 32×32 像素的小块，每块 1 token，每张再加 1。比如 1024×768 是 32×24 = 768 块，计 769 token。切块和缩放的方式和 OpenAI 视觉指南写的一致；指南里的普通视觉模型还要再乘 1.2 等系数，Luna Decisions 实测没有。
  • auto 按原尺寸算；low 先把图缩到 512×512 以内再算，所以每张最多 257 token（正方形图），图越扁越少，不是固定值；high 最多算 2,500 块，所以特别大的图用 high 反而比 auto 便宜。
  • 1024 像素以内的图，high 和 auto 完全一样。
  • 实测 E 的几组照片在各种 detail 下都答对了（房子是红色）。

拒答

直连 OpenAI 的原生接口时，被拒答的题会返回 type: "refusal" 的答案，其他题照常返回。但通过 OpenRouter 调用时不一样：

通过 OpenRouter：一道题被拒答，整个请求失败

只要有一道题被拒答，整个请求就返回 HTTP 502，错误信息是 OpenAI refused to answer question "orientation"，同一请求里的其他题也拿不到答案。

我们的测试题是推断一个人的性取向，属于敏感个人信息推断。遇到这种情况，重试没用，需要换个问法。

OpenAI 对 /v1/decisions 的数据政策

以下适用于直连 OpenAI：

  • 不用于训练；滥用监控日志最多保留 30 天。
  • 符合条件的客户可以用零数据保留（ZDR）；签署 BAA 后可用于 HIPAA 场景。
  • 上传的图片会做 CSAM（儿童性虐待内容）扫描。
  • 数据驻留：请求数据可以存放在美国、欧洲（EEA + 瑞士）、英国、日本、韩国、新加坡、印度、澳大利亚、加拿大、阿联酋，但在当地处理请求（区域处理）只支持美国和欧洲。美国以外的地区要先通过 OpenAI 的审批，数据驻留端点另加 10% 费用。

通过 OpenRouter 调用时，还要同时适用 OpenRouter 自己的数据政策。

11在 Simple Jev 里使用 Luna

为了接入 Luna，调用工具里新增了这些功能：

  1. 选模型。模型下拉框里新增“GPT-6 Luna Decisions（OpenAI，支持图片）”。
  2. 加图片。背景内容下方可以点击选择、拖拽或粘贴图片。每张图都会在浏览器里重新画成最长边不超过 1024 像素的 JPEG：透明的部分填成白色（否则模型会把它看成黑色），照片里的 EXIF 信息（比如拍摄地点）也不会发出去。每次最多 8 张（网页自己的限制，低于 Luna 的 128 张）。图片只在内存里，不保存到浏览器，点「清空」时一起清掉。
  3. 只有支持图片的模型才能上传。选 Jev 这类纯文字模型时，图片区域会禁用并说明原因（Jev 收到图片会乱猜而不报错）。填自定义模型名称时，会去 OpenRouter 模型目录查它是否支持图片。
  4. 选图片精度。选 Luna 并加了图片后，可选“自动”或“低”：自动每张最多约 1,000 token；低先缩到 512 像素以内，每张最多约 260 token。网页发出的图不超过 1024 像素，这时“高”和“自动”完全一样，所以没有提供“高”。其他图片模型（如 Clef）不理会这个设置，选它们时不显示。
  5. 查看原始请求。原始请求和 curl 命令里的图片 base64 会截断显示。
  6. 拒答提示。Luna 拒答时（HTTP 502 + “refused to answer”），会显示“模型拒绝回答这道题”，并说明重试没用、需要换个问法。
